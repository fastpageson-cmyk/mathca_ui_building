# Developer Handoff Notes

이 파일은 기획/마케팅팀에서 디자인 시안을 개발팀에 전달할 때 필요한 요구사항과 기술적 결정사항을 모아두는 문서입니다.

---

## 1. 매칭 리포트 및 메시지 관리 시스템 (Matching Report)

### 📌 기획 요구사항
* **마케팅 멘트 관리 분리**: 매칭 리포트(공통점, 첫인사 팁, 시너지 등)에 들어가는 코멘트는 마케팅팀에서 실시간 분석 결과에 따라 자주 수정하고 업데이트해야 합니다. HTML 코드 내부에 하드코딩되지 않도록 **코멘트 템플릿 데이터를 독립된 파일(JSON 또는 DB/CMS)로 분리해 관리**하기 용이하게 구축해주세요.
* **이메일 발송 자동화**: 템플릿을 메일 솔루션(AWS SES, Resend, SendGrid 등)과 연동하고, 각 동적 데이터(점수, 매칭 메시지, 자기소개)를 치환 변수(예: `{{score}}`, `{{message}}`)로 치환할 수 있게 바인딩해 주세요.

### 💻 개발팀 확인 필요 사항
* **데이터 관리 방식**:
  - 현재 시안은 `match_messages.json` 구조를 호출하고 있습니다. 이를 DB 테이블로 관리하고 관리자 어드민에서 수정하게 할지, 혹은 지정된 경로의 JSON 설정을 마케터가 업데이트할 수 있는 구조(CMS 연동 등)로 할지 논의가 필요합니다.
* **메일 발송 호환성**:
  - `email_draft.html` 시안은 아웃룩, 지메일 등 주요 메일 클라이언트와의 호환성을 고려해 **인라인 CSS 테이블 레이아웃**으로 설계되었습니다. 발송 엔진에 이 마크업을 연동할 때 스타일이 깨지지 않도록 테스트가 필요합니다.

## 2. 설문 완료 페이지 자기소개 입력란 (Survey Complete Intro Message)

### 📌 기획 요구사항
* **상대에게 전해줄 자기소개 한마디**: 설문을 모두 마친 유저가 매칭된 파트너에게 메일과 함께 전달할 한마디를 적는 칸입니다.
* **선택형 입력**: 필수 입력이 아니며, 사용자가 입력하지 않을 경우 이메일 템플릿에서 기본 안내 문구가 대신 출력됩니다.
* **최대 글자 수**: 100자 (바이트 수가 아닌 글자 수 기준)

### 💻 개발팀 확인 필요 사항
* **DB 필드 설계**:
  - 유저 테이블 또는 설문 답변 테이블에 `intro_message` (VARCHAR(100), NULL 허용) 필드를 추가하고 저장해야 합니다.
* **조건부 렌더링 (Fallback)**:
  - 사용자가 자기소개를 작성하지 않았을 경우(`NULL` 또는 빈 문자열), 매칭 이메일(`email_draft.html` 및 `report.html`)의 상대방 자기소개란에 기존 기본 안내 문구(예: *"상대에게 먼저 메일을 보내 가볍게 인사해 보세요."*)가 출력되도록 분기 처리해야 합니다.
* **부적절한 단어 필터링**:
  - 비속어나 부적절한 표현을 1차 필터링하는 정책이나 검증 로직 도입 검토가 필요합니다.

---

## 3. 매칭 제외 스위치 (Exclusion Switch)

### 📌 기획 요구사항
* **제외 설정**: "다음 매칭에서 나를 제외해주세요" 스위치를 켜면 사용자를 매칭 대상 풀(Pool)에서 제외시킵니다. 언제든 해제할 수 있어야 합니다.

### 💻 개발팀 확인 필요 사항
* **API 동기화**:
  - 토글 스위치 활성화/비활성화 시 상태가 DB에 즉시 비동기 통신(AJAX/Fetch API)으로 반영되어 저장되어야 합니다.
  - 필드 예시: `is_excluded` (BOOLEAN, 기본값 `FALSE`)
